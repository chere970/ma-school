# The Tenant Module

This becomes the heart of the system.

It owns things like:

```text
Tenant

id
name
slug
domain
logo
email
phone
timezone
country
currency
subscriptionPlan
status

createdAt
updatedAt
```

Every university is represented by one `Tenant`.

Example:

```text
Tenant 1

Addis Ababa University
```

```text
Tenant 2

Jimma University
```

```text
Tenant 3

Hawassa University
```

Each has its own users, students, and academic data, isolated from the others.

# Authentication Flow

Instead of a simple login:

```
Email
Password
```

We'll authenticate like this:

```
Request

↓

Tenant Resolver

↓

JWT Authentication

↓

RBAC

↓

Controller

↓

Service

↓

Database
```

The application first determines **which university** the request belongs to, then authenticates the user within that tenant.

## One recommendation before we write any business logic

Since this project will likely become your portfolio centerpiece, I recommend we first design the **complete database schema (Prisma)** for the core entities—Tenant, User, Roles, Faculties, Departments, Programs, Students, Instructors, Courses, Semesters, and Registrations.

Getting the schema right early will make the rest of the implementation much smoother and reduce the need for breaking changes later. After that, we can implement the modules one by one on top of a solid foundation.
